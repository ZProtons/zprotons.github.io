FuzzForge

A command-line utility that generates candidate paths, parameter names, and virtual-host names from a target's visible context, then can optionally run ffuf with baseline-aware filtering.

View repository ↗
02Problem

Generic wordlists lack target context.

Traditional content discovery often starts with broad wordlists that contain many candidates unrelated to the application being tested. FuzzForge takes a different approach: it reads the target homepage and uses available context—such as title, navigation links, visible copy, and response-header technology hints—to generate a shorter, target-aware candidate list.

03Workflow

Context, generation, then optional fuzzing.

  1. Fetch the authorised target homepage and extract visible context.
  2. Send the context to a configured OpenAI-compatible chat-completions API.
  3. Generate candidate paths, parameter names, and virtual-host names.
  4. Write each category to its own output file.
  5. Optionally invoke ffuf and filter responses using a known-miss baseline.

It supports hosted and local OpenAI-compatible endpoints through configuration, allowing a local model server to be used.

04Testing & validation

Tested beyond the happy path.

The project includes 23 unit tests using a mocked LLM backend, so the test suite can run without network access or an API key.

It was also verified end-to-end against ClearDesk, a controlled fuzzing lab, using a stub local LLM server and the real ffuf binary. That run exposed workflow issues in baseline selection, exact-path parameter testing, and redirect handling; regression tests were added for the fixes.

05Limitations & responsible use

Useful assistance, not a substitute for judgement.

FuzzForge's parameter mode fuzzes candidate parameter names while using a fixed value (default 1). Applications may depend on a different value, so a negative result does not prove that a parameter is absent or uninteresting.

Use it only against systems you own or are explicitly authorised to test. Generated candidates are hypotheses to validate, not proof of a vulnerability.

See the repository README for installation, configuration, command examples, test notes, and current limitations.
